### Globe — auto-spins + drag changes speed; Trend — 4-week paging (2026-06-17)
- **`DottedGlobe` finger-spin → auto-spin.** User: *"make the globe spinable"* → *"the globe should be spining slowly by itself and my drag can change its speed."* The dot loop now iterates the FULL sphere (`lon` −90…270) and projects only the front hemisphere after a rotation `spinDeg`; the macro hash stays keyed to each dot's TRUE (lat, lon) so the pattern rotates with the sphere (at `spinDeg == 0` the front view is bit-identical to the locked look). Rotation is **analytic** (no per-frame state mutation): `displayedAngle(at:)` integrates `velocity(t) = base + (v0−base)e^(−t/τ)` (`base` 14 °/s, `τ` 1.2 s); a `TimelineView(.animation)` drives the redraw. A `DragGesture` follows the finger (`isDragging` → `dragAngle`), and on release sets `spinVelocity = value.velocity.width · 0.6` (clamped ±720) which eases back to `base`. Reduce Motion freezes the auto-spin (`base` 0, momentum off) — drag still repositions. Edge dots are dimmed by `(90−|displayLon|)/18` for depth. **Continuous Canvas animation — battery cost is intentional; gated off under Reduce Motion.**
- **Calorie trend pages 4 weeks back.** User: *"make the calorie trend scrollable left and right, to allow maximumly 4 weeks … swipe left 4 times, each … one previous week."* `macroSeries(weeksAgo:)` generalizes `last7DaysMacroSeries`; the Today trend is a `TabView(selection: $trendWeekPage)` of `0...maxTrendWeeksBack` (= 4) pages with `.tabViewStyle(.page(indexDisplayMode: .never))`, `.frame(height: 178)`. ### Build + Xcode external-agent access (the user's "utilize it")
- `xcode-select` points at the Command-Line Tools, so a **bare `xcodebuild` fails** ("requires Xcode"). Build via Xcode 26.3 with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild …` (no sudo). Every BUILD SUCCEEDED this session used that.
- Per https://developer.apple.com/documentation/Xcode/giving-external-agents-access-to-xcode, Xcode 26 exposes an MCP server. **Registered:** `claude mcp add --transport stdio xcode --env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer -- xcrun mcpbridge`. To ACTIVATE it the **user** must: Xcode → Settings → Intelligence → turn on "Allow external agents to use Xcode tools," and keep the project open in Xcode. Then the `xcode` MCP tools connect (next session — MCP loads at session start). Until then `claude mcp get xcode` shows "Failed to connect," which is expected.
